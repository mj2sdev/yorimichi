## 내용
### 논의 안건: 프론트엔드와 Spring Security 연동을 위한 HTTP Method 사용 방식

HTML의 `<form>` 태그는 기본적으로 GET과 POST 메소드만 지원합니다. 이로 인해 데이터 수정(PUT), 삭제(DELETE) 등의 작업을 어떻게 처리할지에 대한 논의를 진행했습니다.

#### 의견 1: 동기 방식 (GET, POST 활용)
- **내용**: HTML `<form>` 태그의 기본 동작을 최대한 활용하여 GET과 POST 메소드만으로 대부분의 기능을 구현합니다.
- **장점**:
    - Thymeleaf의 링크 관련 기능(`@{...}`)을 적극적으로 활용할 수 있습니다.
    - 동기 방식으로 처리되므로, 현재 수업에서 배운 내용과 흐름이 일치하여 구현이 용이합니다.

#### 의견 2: 비동기 통신 (Fetch/AJAX 활용)
- **내용**: JavaScript의 Fetch API나 AJAX를 사용하여 PUT, DELETE 등 다양한 HTTP 메소드를 사용하는 비동기 통신으로 처리합니다.
- **장점**:
    - 비동기 통신에 대한 실무적인 경험을 쌓을 수 있습니다.
    - Spring Boot 백엔드 로직을 RESTful API 설계 원칙에 맞게 구현할 수 있습니다.

### 결정 사항
- 여러 논의 끝에, RESTful API 설계 경험과 기술 스택 확장성을 고려하여 **의견 2(비동기 통신 방식)**로 진행하기로 결정했습니다.
- **추가 요청**: 프론트엔드 작업 시, 결정된 API 엔드포인트를 `endpoint.md` 파일에 문서화하여 공유할 것을 요청했습니다.
