# HTTP 메소드에 관한 문서

## 1. HTTP 메소드 개요
HTTP 메소드는 클라이언트와 서버가 어떻게 상호작용할지를 정의하는 요청 방식이다.  
주로 리소스를 조회, 생성, 수정, 삭제하는 역할을 담당한다.

## 2. 역사와 정의
- HTTP/0.9 (1991): 단순히 `GET` 메소드만 존재.
- HTTP/1.0 (1996): `POST`, `HEAD` 추가.
- HTTP/1.1 (1997): `PUT`, `DELETE`, `OPTIONS`, `TRACE` 등 확장.
- HTTP/2, HTTP/3: 메소드 자체는 동일하나 성능과 전송 방식 개선.

## 3. HTTP 메소드 종류와 사용처

| 메소드 | 설명 | 주 사용처 |
|--------|------|-----------|
| GET | 리소스 조회 | 페이지 로딩, 데이터 조회 |
| POST | 리소스 생성, 데이터 전송 | 회원가입, 글 작성 |
| PUT | 리소스 전체 교체 | 데이터 전체 업데이트 |
| PATCH | 리소스 일부 수정 | 특정 필드 업데이트 |
| DELETE | 리소스 삭제 | 데이터 삭제 |
| HEAD | 헤더만 조회 | 리소스 존재 여부 확인 |
| OPTIONS | 사용 가능한 메소드 확인 | CORS 사전 요청 |
| TRACE | 요청을 그대로 반환 | 디버깅 용도 |

## 4. 자주 쓰는 메소드
- **GET**: 데이터 읽기
- **POST**: 데이터 전송 및 생성
- **PUT/PATCH**: 데이터 업데이트
- **DELETE**: 데이터 삭제

## 5. 사용 팁과 주의사항
- GET 요청에는 **민감한 데이터**를 포함하지 말 것 (URL에 노출됨).
- POST/PUT은 멱등성(Idempotency)을 구분해야 한다.  
  - PUT은 멱등적 (같은 요청 반복 → 결과 동일).  
  - POST는 비멱등적 (같은 요청 반복 → 새로운 리소스 생성 가능).
- DELETE도 멱등적이어야 한다. (여러 번 호출해도 결과는 동일).
- PATCH는 부분 수정이므로 스키마 설계에 주의 필요.
- OPTIONS는 CORS 환경에서 자주 마주치므로 브라우저 동작을 이해해야 한다.

## 6. 마무리 한마디
HTTP 메소드는 단순한 규칙이 아니라 웹의 언어다.  
적절히 사용하면 서버와 클라이언트의 의사소통이 명확해지고,  
잘못 쓰면 보안 취약점이나 데이터 혼란을 불러올 수 있다.  
"도구는 정확히 쓸 때 가장 강력하다."
