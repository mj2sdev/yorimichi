# 변수의 생명 주기

변수는 자신이 선언된 위치에서 생성되고 소멸한다.  
전역변수는 애플리케이션의 생명주기와 같다  
함수 내부에서 선언된 지역 변수는 함수가 호출되면 생성되고 종료하면 소멸한다.

보통은 지역변수의 생명주기와 함수의 생명 주기가 일치하지만  
간혹 지역변수의 주소값을 함수 외부로 넘기는 경우에는 그 주소의 할당이 해제되기 전까지는 메모리 영역에 남아있기 때문에 함수보다 더 오래 살아남는 경우도 있다.
즉 변수의 생명 주기는 정확히는 메모리 공간이 확보된 시점부터 메모리 공간이 해제되어 가용 메모리 풀에 반환되는 시점까지다.

# 번역 변수의 문제점

1. 어디서든 참조 가능: 가독성이 나빠지고 의도치않게 상태가 변경될 수 있는 위험성 존재
2. 긴 생명 주기: 이름이 중복 될 가능성이 존재함
3. 검색 속도가 느림: 큰 차이는 없지만 차이가 존재함
4. 네임스페이스 오염: 파일이 분리되어 있다 해도 하나의 전역 스코프를 공유한다는 것. 오류 발생 가능

# 해결법

1. 즉시 실행 함수를 사용한다
2. 네임스페이스 객체를 만들어 사용한다.(그냥 객체 하나 만들어서 거기서 전역변수처럼 가져다 쓰라는 뜻)
3. 모듈 패턴(클로저에 대한 이해 없이 알 수 없다.) 보통은 정보 은닉을 구현하기 위해 사용한다.
4. ES6에서 제공하는 모듈을 이용한다.
